# 战斗机制说明（玩家属性 / 伤害 / 防御 / 元素 / 魂骨）

> 本文是「科技与魔法」战斗系统的实现基准。数值与公式均可调，改动后请同步本文与代码。
> 对应代码：`team.xcmt.sam.api.combat.*`、`team.xcmt.sam.content.Combat*`、`team.xcmt.sam.mixin.*`。

---

## 1. 总览

本模组**移除了原版玩家攻击的伤害计算与「跳劈暴击」**，改用 12 项玩家属性驱动一套新结算：

| 环节     | 接管方式                                                       |
| -------- | -------------------------------------------------------------- |
| 玩家攻击 | `PlayerMixin` 重定向 `Player.attack` 内的伤害实参与暴击判定    |
| 玩家受击 | `LivingEntityMixin` 替换 `getDamageAfterArmorAbsorb`（仅玩家） |
| 元素     | 6 个 MobEffect + 强度机制                                      |
| 魂骨     | Curios 6 部位饰品槽位                                          |

保留的原版行为：击退、横扫、音效、统计、饥饿消耗、无敌帧、伤害吸收、死亡保护，
以及受击时 `getDamageAfterMagicAbsorb`（抗性提升 / 附魔保护）。

---

## 2. 玩家属性（12 项）

全部注册在 `minecraft:attribute`，并挂在 `minecraft:player` 上；均 `setSyncable`，可被装备 / 效果修饰。

| 代号 | 属性 id（`attribute.name.science_and_magic.` 之后） | 中文名       | 默认值 | 单位               |
| ---- | --------------------------------------------------- | ------------ | ------ | ------------------ |
| bATK | `base_attack`                                       | 基础攻击力   | 2      | 平值               |
| bDEF | `base_defend`                                       | 基础防御力   | 0      | 平值               |
| BLD  | `blood_counter`                                     | 致命率       | 50     | %                  |
| BLDk | `blood_count`                                       | 致命加伤     | 5      | 平值               |
| pATK | `physic_attack`                                     | 物伤加成     | 0      | %                  |
| mATK | `magic_attack`                                      | 法伤加成     | 0      | %                  |
| sATK | `science_attack`                                    | 科技熟练加成 | 0      | %（本轮预留）      |
| pDEF | `physic_defend`                                     | 物伤防御率   | 0      | %                  |
| mDEF | `magic_defend`                                      | 法伤防御率   | 0      | %                  |
| mEP  | `max_ep`                                            | 魔力值上限   | 0      | 平值（本轮只注册） |
| PE   | `player_energy`                                     | 体魄         | 100    | %                  |
| MC   | `magic_count`                                       | 意志力       | 100    | %                  |

**百分比约定**：属性里 `100` 表示 `100%`，公式内一律除以 100。因此 PE=100 即 ×1.00。

## 3. 伤害流程（7 步）

1. **玩家属性计算最终伤害**
   `(bATK × (1 + 攻击加成%) + 致命加成) × 加权%`
   - 攻击加成按伤害归类取：物理 `pATK` / 法术 `mATK` / 科技 `sATK`
   - 加权：物理用 `PE`，法术与科技用 `MC`
   - 致命加成：以 `BLD%` 概率触发，触发时取 `[0, BLDk]` 区间**均匀随机实数**
2. **武器附加伤害**（`CombatContributors` 的 `ATTACK_WEAPON` 阶段，默认 0）
3. **魂骨附加伤害**（`ATTACK_SOUL_BONE`，默认 0）
4. **装备附加伤害**（`ATTACK_EQUIPMENT`，默认 0）
5. **元素附着加成**：**就是克制判定倍率本身**（固定 ×1.5 / ×0.5 / ×1.0，见 §6.2）；不存在"每级元素增伤"这类平值。
   元素来源（武器附着 / 自身附着）与判定后的「传染」见 §6.4
6. **原版暴击 / 原版生物效果**：原版暴击已被本系统取代；第三方通过 `CriticalHitEvent` 给出的倍率在此叠加
7. **发出伤害**：四舍五入后调用 `hurtServer` / `hurtClient`

> 武器 / 魂骨 / 装备的数值主要由物品自身的属性修饰符表达（见 §7、§8），
> `CombatContributors` 只是「非属性类附加量」的挂载点，当前为空实现。

**示例验算**（bATK=1、pATK=29%、BLDk=2、PE=100%、致命随机到 2）：
`[1 × (1 + 29%) + 2] × 100% = 3.29 → 3`

---

## 4. 防御流程（8 步）

1. **接收伤害**（`hurtServer` 传进来的数值）
2. **玩家防御属性计算**：`bDEF ×（触发防御率时 ×2）× 加权%`
   - 防御率：物理 `pDEF%`、法术 `mDEF%`；触发时**再多挡住一份 bDEF**
   - 加权：物理 `PE`、法术 `MC`
3. **武器防御加成**（`DEFENSE_WEAPON`）
4. **装备防御加成**（`DEFENSE_EQUIPMENT`）
5. **魂骨防御加成**（`DEFENSE_SOUL_BONE`）
6. **元素附着加成 / 减益**：克制判定倍率（仅当攻击方不是玩家时在此结算，避免与伤害侧重复扣减强度）
7. **原版效果加成 / 减益**：`getDamageAfterMagicAbsorb` 原样保留（抗性提升、附魔保护）
8. **最终受到伤害**：`max(伤害 − 最终防御, 0)`，四舍五入

**取整规则**：最终伤害、最终防御、最终受到伤害**全部四舍五入**（`Math.round`），与示例 `3.29 → 3` 一致。

## 6. 元素附着与克制

### 6.1 六元素

| 元素 | 效果注册名         | 贴图                                       |
| ---- | ------------------ | ------------------------------------------ |
| 火   | `element_fire`     | `textures/mob_effect/element_fire.png`     |
| 冰   | `element_ice`      | `textures/mob_effect/element_ice.png`      |
| 电   | `element_lighting` | `textures/mob_effect/element_lighting.png` |
| 岩   | `element_stone`    | `textures/mob_effect/element_stone.png`    |
| 水   | `element_water`    | `textures/mob_effect/element_water.png`    |
| 木   | `element_wood`     | `textures/mob_effect/element_wood.png`     |

元素附着对伤害 / 防御的**唯一影响是克制判定倍率**（见 6.2）——**没有**「每级元素增伤 / 减伤」这类平值。
图标由注册名自动解析，无需额外注册。

### 6.2 克制关系（倍率作用于**攻击方的输出伤害**）

| 关系 | 元素                            | 倍率                       |
| ---- | ------------------------------- | -------------------------- |
| 克制 | 火 → 冰、冰 → 水、水 → 火       | 克制方 ×1.5，被克制方 ×0.5 |
| 自克 | 木/木、石/石、电/电（**增伤**） | 攻击方 ×1.5                |
| 减免 | 木 ⇄ 石                         | 双方 ×0.5                  |
| 其他 | 任意                            | ×1.0                       |

- **双方元素判定**：攻方元素优先取**伤害携带元素**（武器附着，见 6.4），否则取自身附着中**强度最高**者；
  守方元素取自身附着中强度最高者；无附着则不参与关系判定。
- **消耗**：守方只在产生实际关系（倍率 ≠ 1.0）时降一级；攻方按 6.4 的规则消耗。

### 6.3 强度机制

- **强度表示**：MobEffect 的 `amplifier = 强度 − 1`（HUD 显示 I / II / III …）。
- **数值作用**：强度**不影响**伤害 / 防御数值——它只用来决定该实体的「生效元素」（取强度最高者），
  并作为克制结算的消耗资源。因此 256 级也不会放大伤害。
- **叠加**：附着时若已有同元素，强度**相加**。
- **随时间衰减**：时长恒为 **3 秒（60 ticks）**；到期时强度 **−1** 并重新计时。
  例：`水附着 III（3 秒）→ 水附着 II（3 秒）→ …`。
- **克制降级**：一次元素关系结算后，涉事元素各 **−1**，并把时长**重置为 3 秒**（无视原时长）。
- **无视时长**：一切附着 / 叠加 / 降级都强制 `duration = 60`，外部写入的其他时长会被归一化。
- **仅服务端**：强度变更只在服务端执行；客户端只做表现预测。

> ⚠️ **上限**：原版 `MobEffectInstance` 的 `MAX_AMPLIFIER = 255`，故强度上限为 **256 级**。
> 若需要真正「无上限」，需改用 NeoForge DataAttachment 存真实强度、amplifier 仅作显示。

### 6.4 元素来源与「传染」

攻击方的元素按下面的优先级确定：

1. **伤害携带元素** —— 武器上的 `science_and_magic:element_attachment` 组件
   （字段 `element` / `strength`）。读取路径是原版 `DamageSource#getWeaponItem()`，
   即伤害来源的 direct entity 手上的武器，因此**不需要改动原版 `DamageSource`**。
   **所有附着武器统一强度 2**（`ElementAttachmentSpec.WEAPON_STRENGTH`）。
2. 若伤害没有携带元素，回退取**攻击者自身最高强度附着**。

命中时的判定与传染：

1. 用「攻方元素 vs 守方元素」算出克制倍率；
2. 产生实际关系时，守方涉事元素降一级；
3. 攻方的伤害携带元素：
   - **产生克制关系**时按「判定」**消耗 1 级**（二级 → 剩一级）；
   - **不产生克制关系**时**不消耗**；
   若攻方元素来自自身附着且产生了实际关系，则消耗自身附着一级；
4. **传染**：把该元素按「判定后强度」附着到被攻击实体：
   - 产生关系 → 传**剩余强度**（二级武器 → 给目标 1 级）；
   - 不产生关系 → 传**完整强度**（二级武器 → 给目标 2 级）。

> 注：传染发生在服务端（客户端只做只读预测，不改变强度）。

## 9. 兼容适配层（供其他模组接入）

因为删除了原版机制，其他模组需要新的接入点：

### 9.1 事件（游戏总线 `NeoForge.EVENT_BUS`）

| 事件                       | 时机                     | 能力                                                                                                       |
| -------------------------- | ------------------------ | ---------------------------------------------------------------------------------------------------------- |
| `SamAttackEvent`           | 玩家攻击「发出伤害」前   | 改最终伤害 / 改归类 / 改致命状态；取消 = 不造成伤害                                                        |
| `SamDefenseEvent`          | 玩家受击、替换护甲公式前 | 改最终防御 / 直接改最终伤害 / 改归类；取消 = 回退原版护甲公式                                              |
| `CriticalHitEvent`（原版） | 每次玩家攻击             | **仍然触发**：本模组把自身致命判定作为「原版暴击」传入，倍率默认 1.0；第三方对暴击状态与倍率的修改会被采纳 |

### 9.2 API（`team.xcmt.sam.api.combat.CombatApi`）

- `registerContributor(CombatContributor)`：注册附加伤害 / 附加防御（对应各结算阶段）
- `registerTechDamageType(ResourceKey<DamageType>)`：把伤害类型标记为科技类
- `attachElement` / `decayElement` / `elementStrength` / `highestElement`：读写元素强度
- `ElementAttachmentSpec.COMPONENT`：给武器 / 物品挂元素附着的数据组件（`ElementAttachmentSpec.weapon(元素)` 即二级强度）
- `damageCategory(DamageSource)`、`attribute(LivingEntity, Holder<Attribute>)`：查询
- 属性持有者见 `CombatAttributes`（`DeferredHolder<Attribute, Attribute>`，可直接用于 `AttributeModifier`）

## 10. 已知取舍与限制

1. **原版暴击倍率消失**：原版 `ATTACK_DAMAGE × 1.5` 不再生效，暴击完全由 BLD / BLDk 决定；
   触发致命时由本系统补播 `PLAYER_ATTACK_CRIT` 音效与粒子。
2. **附魔伤害不再参与**：武器附魔的额外伤害（原版 `magicBoost`）被新公式取代，如需保留应通过 `CombatContributors` 重新加入。
3. **科技类伤害**：`sATK` 仅完成归类与属性注册，尚未参与结算。
4. **元素强度上限 256 级**（见 6.3）。
5. **魂骨物品图标**：仓库暂只有 Curios 槽位图标，物品模型直接复用 `science_and_magic:slot/bone_*`，后续可替换为独立物品贴图。
6. **玩家属性面板 GUI**：本轮未实现（文案与贴图已就绪）。
7. **元素宝珠**：`textures/item/*_init.png`、`models/item/*_init.json`、`geo/init.geo.json`、`animations/init.animation.json` 为废弃稿，本系统不引用。
8. **元素不做平值增伤**：「元素附着加成」**就是克制判定倍率本身**（×1.5 / ×0.5 / ×1.0）。
   早期实现曾按「每元素单位值 × 强度」给平值增伤，256 级强度下会产出数百点伤害
   （实测把 100 HP 的铁傀儡一击秒杀，见 §11 日志），该实现已移除；强度自此只决定「生效元素」与消耗节奏。

### 11.1 调试命令（仅测试用）

| 命令                                      | 说明                                                           |
| ----------------------------------------- | -------------------------------------------------------------- |
| `/samcombat debug <true\|false>`          | 开关 `[SAM-COMBAT]` 侦测日志（需要游戏管理员权限）             |
| `/samcombat element <元素> <强度> [目标]` | 给目标施加元素附着（省略目标则作用于自己），走本模组的叠加规则 |

元素取值：`fire` / `ice` / `wood` / `water` / `lighting` / `stone`。
例如 `/samcombat element water 3` 得到「水附着 III」，3 秒后自动降为 II，再 3 秒降为 I，再 3 秒消失。

对应实现：`team.xcmt.sam.event.CombatCommands`、`team.xcmt.sam.event.CombatDiagnostics`。
