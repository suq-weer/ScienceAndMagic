# 自定义树木建筑要求（NBT 蓝图 / 形状 / 预设）

> 本文是「科技与魔法」树形系统的**蓝图制作基准**。搭出来的树能不能被正确识别、锚点会不会偏、
> 树根铺不铺得满树苗矩阵，全部由下面这些约定决定。
> 对应代码：`team.xcmt.sam.api.wood.TreeShape` / `TreePreset` / `TreePresetCatalog` /
> `TemplateAnchors` / `TemplateTreeShape` / `PlacerTreeShape` / `TreeShapes` / `WoodTreeFeatures`、
> `team.xcmt.sam.content.WoodTemplateFeature` / `WoodSwapProcessor` / `WoodSaplingBlock` /
> `TreePresetFile` / `TreePresetCatalogLoader`、
> `team.xcmt.sam.datagen.TreeSourceLoader` / `BlueprintValidator` / `WoodTreePresetProvider`、
> `team.xcmt.sam.util.WoodBlockRemapper`。

---

## 0. 一分钟版本

把一张 `.nbt` 丢进这个目录，然后重跑一次数据生成：

```
src/main/resources/gen/tree_shapes/<预设>/<N>x<N>/<名称>.nbt
```

```bash
./gradlew runData          # 编译 + 校验；有任何问题都会在这里失败并说明原因
```

进游戏后 `/reload` 即可生效（**不需要重启**）。

**五条硬性要求**（其余都是自动的）：

1. `<N>x<N>` 必须与**树干最低一层的水平足迹**完全一致（3x3 树干 → 放 `3x3/`）；
2. 树干最低一层必须是**一整块 NxN 实心木质方块**，不能空心、缺角、L 形；
3. 树干用 `minecraft:oak_log`（或 `oak_wood` / 去皮变体）标记，树叶用 `minecraft:oak_leaves`；
4. 树苗矩阵边长上限 **8x8**（`TreePreset.MAX_MATRIX_SIZE`）；
5. 改完**必须重跑 `runData`**，否则游戏读到的是旧的编译产物。

## 1. 三层结构（先理解这个，后面都是细节）

```
src/main/resources/gen/tree_shapes/…  ← ① 手写源：你编辑的地方（与 data/、assets/ 同级）
        │
        │  ./gradlew runData        ← ② 编译 + 唯一校验关卡（不通过就失败）
        ▼
src/generated/resources/data/science_and_magic/
  tree_preset/<预设>.json          ← ③ 编译产物：桶 / 权重 / 每区块次数
  structure/tree_shapes/<预设>/<N>x<N>/<名称>.nbt   ← 蓝图字节副本
  worldgen/configured_feature/…    ← 每个形状 × 每个木种的地物
        │
        │  进入游戏（或 /reload）    ← ④ 运行时只消费产物
        ▼
TreePresetCatalog（静态目录） + StructureTemplateManager（蓝图）
```

**为什么源放在 `src/main/resources/gen/` 而不是 `data/` 里**：`gen/` 是数据生成的**输入**，
不是运行时的数据。原版资源系统只读 pack 根下的 `data/` 与 `assets/`，所以 `gen/` 既不会被当成
数据包内容，又能和 `data/`、`assets/` 平级地摆在源码树里；运行时读的是 `runData` 产出的编译产物
——这也正是「`runData` 通过 = 游戏里一定不会因为数据问题出错」的由来。

> `gen/` 会被 `processResources` 一起打进 mod 包。若不想在分发产物里带上源码，
> 在 `build.gradle` 的 `sourceSets.main.resources` 里加一行 `exclude('gen/**')` 即可；
> 那不影响 `runData`——它是按注入的绝对路径读**源码树**，不读构建产物。

**为什么蓝图副本必须落回 `structure/`**：原版 `StructureTemplateManager` 只认
`data/<命名空间>/structure/**`，而 `src/main/resources/gen/` 不在 `data/` 之下。

> ⚠️ 蓝图副本是**原样字节复制**（不去空气、不归一化），所以可以用 SHA1 直接对照源与产物。

## 2. 目录约定

```
src/main/resources/gen/tree_shapes/
├─ <预设>/
│  ├─ _preset.json                        ←（可选）每区块尝试次数、桶权重
│  └─ <N>x<N>/
│     ├─ <名称>.nbt                        ← NBT 蓝图，权重 1
│     ├─ <名称>@<权重>.nbt                 ← 同上，带权重
│     ├─ <内置形状>.shape                  ← 引用代码几何，权重 1
│     └─ <内置形状>@<权重>.shape           ← 同上，带权重
└─ ...
```

| 概念 | 由什么决定 | 例子 |
| --- | --- | --- |
| 预设 id | 一级目录名 | `tree_shapes/fancy/` → `science_and_magic:fancy` |
| 桶 key（矩阵边长 N） | 二级目录 `<N>x<N>` | `3x3/` → N = 3 |
| 形状 id | `<预设>/<N>x<N>/<名称>` | `science_and_magic:fancy/3x3/fancy_big_tree` |
| 蓝图 id（编译产物里） | `tree_shapes/<预设>/<N>x<N>/<名称>`（**不带 `structure/`**，见下） | `science_and_magic:tree_shapes/fancy/3x3/fancy_big_tree` |
| 权重 | 文件名里的 `@数字`，缺省 1 | `oak@9.shape` → 权重 9 |

形状 id 带你所在的**预设与桶**，所以同一张蓝图放在两个预设里不会撞名；地物 id 由
`<木种>_tree_<N>x<N>_<名称>` 组成。

> **「文件路径」和「资源 id」不是一回事**，这里最容易写错。原版读盘用
> `FileToIdConverter.json("structure")`，它会把 `structure/` 前缀**剥掉**，正如
> `data/<ns>/recipe/x.json` 的 id 是 `<ns>:x` 而不是 `<ns>:recipe/x`。所以：
>
> | | 值 |
> | --- | --- |
> | 蓝图文件 | `data/science_and_magic/`**`structure/`**`tree_shapes/fancy/3x3/fancy_big_tree.nbt` |
> | 它的模板 id | `science_and_magic:tree_shapes/fancy/3x3/fancy_big_tree`（**无** `structure/`） |
>
> 这两个值由 `TemplateTreeShape` 从同一个「形状路径」推出，你不需要手写其中任何一个。

## 3. `runData` 的校验清单（唯一的把关点）

`runData` 会**一次收集全部问题再统一报出**（不是遇到第一个就停），所以一轮就能改完所有毛病。

| # | 检查 |
| --- | --- |
| 1 | 目录层级必须是 `<预设>/<N>x<N>/<文件>`，或 `<预设>/_preset.json` |
| 2 | 桶目录必须是正方形 `<N>x<N>`，且 `N ≤ 8` |
| 3 | `_preset.json` 必须是合法 JSON；`placement_count` 是非负整数；`bucket_weights` 键是整数、值为正数；**不认识的字段会直接报错**（防拼写错误） |
| 4 | `.shape` 引用的内置形状必须存在，且其 size 与桶目录一致 |
| 5 | 蓝图必须能解析为结构蓝图（NBT 格式正确） |
| 6 | 蓝图必须含木质标记方块（第 4 节的 4 种） |
| 7 | 蓝图的树干足迹必须容得下 NxN（见第 5 节） |
| 8 | 每个预设至少有一个形状（只放 `_preset.json` 不放形状的目录会报错） |
| 9 | 木种引用的预设必须存在（`WoodMaterial` 里的预设 id 写错会在这里炸） |

**为什么是硬失败而不是警告**：形状与地物都是这里生成的，两者天然一致。一旦允许带病通过，
错误就会推迟到游戏里、以「树长不出来 / 树长歪」这种极难排查的形式出现——上一轮就是这么踩的。

## 4. 蓝图里该放什么方块

| 蓝图里的方块 | 放置时会变成 | 说明 |
| --- | --- | --- |
| `minecraft:oak_log` / `oak_wood` / `stripped_oak_log` / `stripped_oak_wood` | 本木种对应的 `log` / `wood` / `stripped_log` / `stripped_wood` | **这四种同时是「树干足迹」的判定标记** |
| `minecraft:oak_leaves` | 本木种的树叶 | |
| 其余 `minecraft:oak_*` 衍生方块 | 本木种的同后缀方块（见下表） | 台阶/栅栏/门等装饰也会跟着换木种 |
| **空气** | **不放置**（等价结构空位） | 所以包围盒可以框得很大，不必裁剪 |
| 其他方块（`stone` / `moss_block` / 藤蔓…） | **原样放置** | 用来做树根、苔藓、装饰 |

橡木系**全量替换表**（20 种后缀，属性会按「目标方块也有的同名属性」保留，朝向/半砖/栅栏连接不会丢）：

```
log          wood          stripped_log   stripped_wood
planks       stairs        slab           fence
fence_gate   door          trapdoor       button
pressure_plate  sign       wall_sign      hanging_sign
wall_hanging_sign  shelf   leaves         sapling
```

**两个常见误解**：

- 不需要自己把空气挖掉——空气不会被放置，原地形保留；
- 不需要把树干摆到包围盒的角上——锚点由代码按「树干足迹」自动检测（见下一节）。

## 5. 锚点：树干足迹必须 NxN（最重要的一节）

放置时要回答一个问题：**蓝图的哪个格子对齐到树苗矩阵的西北角？** 这个「哪个格子」就是锚点。

### 5.1 算法（4 步）

1. 收集蓝图里全部**木质标记方块**（第 4 节的 4 种），按 Y 分层；
2. 自最低层起逐层跑「最大实心正方形」DP：

   ```
   dp[x][z] = 以 (x,z) 为东南角的最大实心木质方格边长
   ⟹「以 (x0,z0) 为西北角的 NxN 全填充」等价于 dp[x0+N-1][z0+N-1] >= N
   ```

   取**第一个**「最大边长 ≥ N」的层，这一层就是**树干基底**；
3. 在该层枚举所有「以 (x,z) 为西北角的 NxN 全填充」候选；
4. 用**上一层（y+1）的木质方块支撑度**消歧——树干是竖直连续的，哪块 NxN 上方木质方块最多，
   哪块就是真树干；支撑度并列时取 `x` 最小、再取 `z` 最小（保证同一张蓝图永远得到同一锚点）。

最后把锚点的 **X/Z 对齐到树苗矩阵西北角、Y 对齐到树苗所在的 Y**。

### 5.2 具体例子

`src/main/resources/gen/tree_shapes/fancy/3x3/fancy_big_tree.nbt`：树干在包围盒里**并不贴角**。

```
树干故意放在局部 x,z 从 2 开始 —— 这正是为了验证锚点不是靠「局部原点」得来的
判定结果：最低合格层 y=0，取该层 NxN 候选并比上一层支撑度 → 锚点 (2,0,2)
放置时 position = origin - (2,0,2)，树干于是恰好铺满树苗矩阵
```

### 5.3 多解会被怎么处理

底部铺开的树根、不规则切面都会让同一层出现**多个** NxN 候选。代码不做平面搜索，
而是**用上一层消歧**（第 4 步）。例如：

```
y=0：树根铺成 4x4（含多个 3x3 候选）
y=1：真正的树干 3x3 只在某一处 → 该处支撑 9/9，其余候选 0/9 → 唯一命中
```

若某一层所有候选的上方支撑都为 0（例如树干只有 1 格高），则退化为「取最小 x、再最小 z」，
行为依然是确定的、可复现的。

### 5.4 足迹容不下 NxN 会怎样

**`runData` 直接失败**，并给出逐层诊断：

```
树形源校验失败（1 项），runData 中止：
  - tree_shapes/fancy/3x3/bad.nbt：树干足迹容不下 3x3。自最低层起各层的最大实心木质方格为
    [2, 2, 2, 2, 2, 2]（全图最大 2x2）。请确认树干最低那一层是一整块 3x3 的木质方块
    （不能空心 / 缺角 / L 形），或者把这张蓝图移到与它树干足迹相符的 <N>x<N> 桶目录下
```

**这类错误进不了游戏**。「各层最大实心木质方格」这个列表就是诊断依据：全是 2 说明树干只有 2x2，
中间有个 3 说明某层缺角。

### 5.5 竖直方向的对齐

锚点层的 Y 对齐到**树苗所在的 Y**（也就是地面之上那一格）。因此：

- 锚点层**之下**的方块会落到**地面以下**——这对「树根插进土里」是想要的效果；
- 所以「底部铺开、但构不成 NxN 的树根」会被自然跳过（它不在合格层里），不会把锚点带偏。

## 6. 生长行为（树苗矩阵）

树苗是 `WoodSaplingBlock`，生长逻辑**不再受原版 1x1 / 2x2 的限制**：

| 行为 | 说明 |
| --- | --- |
| 矩阵尺寸 | 支持 1x1、2x2、3x3……上限 **8x8**（`TreePreset.MAX_MATRIX_SIZE`） |
| 触发 | 随机刻或骨粉，走原版两段式 `STAGE`：第一次先推一格，第二次才生长 |
| 选桶 | 从**最大桶**往下找第一个「包含触发位置、全为同种树苗」的 NxN 方阵，用那个 N 的桶 |
| 抽签 | 桶内按**权重**随机抽一个形状 |
| 清空 | 先清空整块 NxN 矩阵，再放置；**放置失败会把树苗原样恢复** |
| 判定 | 只看方块是不是同一种树苗，不要求 `STAGE` 一致 |

> 只要求「同一种树苗」，所以 3x3 里混着 `stage=0/1` 的树苗也能长。
> 触发位置优先当作矩阵西北角，因此用骨粉点方阵的西北角那株行为最直观。

## 7. 自然生成

每个木种只挂**一个** placed feature `<木种>_trees`，类型是 `minecraft:weighted_random_selector`：

```
每次放置尝试 → 在「全部桶的并集」里按权重抽一个形状 → 放置
权重 = 形状权重 × 桶权重        桶权重默认 = 1 / N²
```

于是 3x3 巨树被抽中的概率只有 1x1 的 1/9，不会满地巨树。放置修饰符为
`count(placement_count)` + `in_square` + `heightmap(OCEAN_FLOOR)` + `would_survive(树苗)` + `biome`，
注入群系取自 `WoodMaterial.biomeTags()`。

**`placement_count` 怎么定**：旧模型里每个形状各有独立的每区块尝试次数，新模型是木种级单一计数，
所以取「桶内各形状旧次数之和」即可保持森林密度（现有预设都是这么定的，例如 `conifer` = 5，
来自旧的 `pine 4 + mega_pine 1`）。

## 8. 权重与 `_preset.json`

**权重**写在文件名里（`@` 之后），桶内归一化：

```
oak@9.shape + fancy_oak@1.shape   → 90% 橡木 / 10% 花式橡木（精确复刻原版概率）
spruce.shape + pine.shape         → 50 / 50
```

**可选的 `_preset.json`**（放在预设目录下，与 `<N>x<N>` 同级）：

```json
{
  "placement_count": 5,
  "bucket_weights": { "1": 1.0, "3": 0.11 }
}
```

| 字段 | 默认 | 含义 |
| --- | --- | --- |
| `placement_count` | `1` | 自然生成时每区块的尝试次数（`0` = 该木种完全不自然生成） |
| `bucket_weights` | `1/N²` | 覆盖某个桶在自然生成时的抽样权重；键是边长 N 的字符串 |

> 注意：`bucket_weights` 只影响**自然生成**，不影响树苗生长时的桶内加权抽签。
> 写错字段名（例如 `placementCount`）会在 `runData` 报「不认识的字段」。

## 9. 引用内置代码几何（`.shape`）

不想搭蓝图时，可以直接引用内置的 12 种原版几何——建一个**空文件**，文件名就是形状名：

```
src/main/resources/gen/tree_shapes/spruce/1x1/spruce.shape          → 引用内置 science_and_magic:spruce
src/main/resources/gen/tree_shapes/spruce/1x1/pine@1.shape          → 同上，权重 1
```

文件名必须是附录 A 里的名字，且**内置形状的 size 必须与桶目录一致**，否则 `runData` 会失败：

```
tree_shapes/fancy/2x2/xxx.shape：未知的内置形状 xxx；可用：oak, fancy_oak, birch, spruce, ...
tree_shapes/fancy/2x2/pine.shape：内置形状 pine 需要 1x1 的矩阵，不能放进 2x2 桶
```

## 10. 把预设挂到木种上

新增木种时，在 `ModBlocks` 里把预设 id 传给 `WoodMaterial`（一行）：

```java
WoodMaterial.of(
        ScienceAndMagic.MOD_ID, "sequoia", "红杉木", palette,
        ScienceAndMagic.id("conifer"),      // ← 预设 id，对应 src/main/resources/gen/tree_shapes/conifer/
        true, true)
```

预设 id 不存在时，`runData` 会直接抛异常（不会静默变成「树苗怎么也不长」）：

```
木种 sequoia 引用了不存在的树形预设 science_and_magic:xxx；
请检查 src/main/resources/gen/tree_shapes/ 下是否有同名目录，改完后重跑 runData
```

## 11. 排错

### 11.1 正常日志

```
# runData 期间（也能一眼看到桶分布与权重）
树形预设 science_and_magic:fancy：3x3=fancy_big_tree@1, 2x2=dark_oak@1, 1x1=cherry@9+fancy_oak@1（每区块 1 次）
树形源 D:\…\src\main\resources\gen\tree_shapes：9 个预设、1 个蓝图副本

# 进入世界后（同样一行，来自运行时目录装载）
树形预设 science_and_magic:fancy：…
树形蓝图：已预热 1 张（锚点同时进入缓存）
```

### 11.2 `runData` 失败（数据问题，改完重跑）

| 消息片段 | 含义 |
| --- | --- |
| `树干足迹容不下 3x3。自最低层起各层的最大实心木质方格为 […]` | 蓝图树干足迹与桶目录不匹配（见 5.4） |
| `无法解析为结构蓝图` | 不是结构方块导出的合法 NBT |
| `没有识别到任何木质标记方块` | 树干没用 `oak_log` 类方块标记 |
| `未知的内置形状 …` / `需要 1x1 的矩阵，不能放进 2x2 桶` | `.shape` 文件名写错，或 size 与桶不符 |
| `桶目录必须形如 <N>x<N>` / `必须是正方形` / `边长上限是 8` | 桶目录名不合法 |
| `不认识的字段 …` | `_preset.json` 里有拼写错误的键 |
| `这个预设下没有任何形状` | 建了预设目录但没放任何 `<N>x<N>/` 文件 |
| `引用了不存在的树形预设 …` | `WoodMaterial` 里的预设 id 没有对应目录 |
| `找不到树形源目录 tree_shapes` | 不是通过 `./gradlew runData` 跑的（`src/main/resources/gen` 路径靠构建脚本注入） |

### 11.3 运行期 ERROR（数据包覆盖 / 产物缺失才会出现）

| 消息片段 | 含义 |
| --- | --- |
| `树形预设目录读不到任何文件（data/*/tree_preset/*.json）` | **WARN**。没有跑过 `runData`，或数据包删掉了产物 |
| `树苗的树形预设 … 不存在` | 该预设的 JSON 不在数据包里，树苗不会生长（只报一次） |
| `蓝图文件无法解析（NBT 可能损坏），已跳过这个形状` | 数据包覆盖了蓝图且内容损坏（只报一次） |
| `找不到蓝图（或它是空的）` | 数据包删掉了蓝图 |
| `木种 … 的形状 … 缺少地物 …` | 数据包删掉了地物。**不会**退化成更小的树（只报一次） |
| **症状：摆再大的树苗矩阵都只长出 1x1** | 见上一行；修复 = `./gradlew runData` + `/reload` |

> 运行期只保留「数据包可能破坏什么」这一类防御，格式与足迹校验全部前移到了 `runData`。

## 12. 热更新边界

| 改动 | 生效方式 |
| --- | --- |
| 改 `.nbt` / `.shape` / `_preset.json` 的内容 | `runData` → `/reload`（**不需要重启**） |
| **新增 / 删除** `.nbt`、`.shape`、预设目录 | `runData` → `/reload`（同样不需要重启） |
| 改木种引用的预设 id（Java 代码） | 重跑 `runData` + 重启游戏（改了 Java 必须重启） |

> 为什么能做到不重启：预设与形状**没有进 NeoForge 静态注册表**（注册表在启动阶段就冻结，
> 而数据包在那之后才加载）。它们走的是「`src/main/resources/gen/` 源 → `runData` 编译 → 数据包产物 →
> 运行时数据包重载监听器装配静态目录」这条链路，因此 `/reload` 就能整套换新。
>
> 附带好处：**数据包也可以直接新增 / 覆盖预设**——写一份 `data/<ns>/tree_preset/<预设>.json`
> 并配上自己的地物即可，格式见 `TreePresetFile`。

## 13. 制作流程与自检清单

**流程**

1. 搭树（结构方块，或直接用 `tools/make_demo_tree_nbt.ps1` 生成）；
2. 量出**树干最低一层的水平足迹** → 这就是 N；
3. 定预设名（复用现有预设，或新建 `src/main/resources/gen/tree_shapes/<新预设>/`）→ 把文件放到 `<N>x<N>/`；
4. 需要就加 `_preset.json` 调密度 / 桶权重；
5. `./gradlew runData` —— **把所有问题都在这一步解决掉**（它会一次列全）；
6. 启动游戏（或 `/reload`），日志里应出现该预设的桶分布；
7. 创造模式用骨粉验证：1x1 单株、以及摆出 NxN 矩阵；
8. 确认外观没问题，再放进群系（`biomeTags`）。

**自检清单**

- [ ] `<N>x<N>` 与树干最低层足迹一致
- [ ] 树干最低层是**完整 NxN 实心**木质方块（不是 L 形 / 空心 / 缺角）
- [ ] 树干用了 `oak_log` / `oak_wood` / 去皮变体，树叶用了 `oak_leaves`
- [ ] 文件在 `src/main/resources/gen/tree_shapes/<预设>/<N>x<N>/` 之下
- [ ] 文件名没有非法字符；带权重时形如 `名称@9.nbt`
- [ ] 空气没有手工挖掉（无所谓，会被跳过）
- [ ] 树干最低层之下没有需要浮空的方块（会落到地面以下）
- [ ] `./gradlew runData` **通过**（没有 `树形源校验失败`）
- [ ] 进游戏后日志里能看到该预设的桶分布（说明数据包产物已生效）
- [ ] 树苗生长与自然生成都验证过（两者用的是同一份形状数据）

## 14. 演示蓝图与工具

**当前仓库里的蓝图**：`src/main/resources/gen/tree_shapes/fancy/3x3/fancy_big_tree.nbt`（手搭，已通过 `runData` 校验）。

```powershell
# 正例：3x3 树干的演示蓝图（树干故意不贴包围盒的角，用于验证锚点检测）
# 默认输出到 src/main/resources/gen/tree_shapes/conifer/3x3/tower.nbt —— 注意这会给 conifer 添一个 3x3 桶
pwsh -NoProfile -File tools/make_demo_tree_nbt.ps1

pwsh -NoProfile -File tools/make_demo_tree_nbt.ps1 -TrunkSize 2 `
     -Out src/main/resources/gen/tree_shapes/fancy/3x3/bad.nbt
```

| 脚本参数 | 默认 | 含义 |
| --- | --- | --- |
| `-Out` | `src/main/resources/gen/tree_shapes/conifer/3x3/tower.nbt` | 输出路径 |
| `-TrunkSize` | `3` | 树干水平边长（决定它该放进哪个 `<N>x<N>`） |
| `-TrunkHeight` | `6` | 树干高度 |

> 结构方块导出的 `.nbt` 保存位置在**存档目录**里（`<存档>/generated/<命名空间>/…`），
> 复制到 `src/main/resources/gen/tree_shapes/` 下的对应桶目录即可；找不到时直接按文件名搜索最稳。
